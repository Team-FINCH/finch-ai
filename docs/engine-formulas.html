§2Portfolio Engine

2.1 평가금액과 비중

Valuation
MV_i = q_i × P_i V = Σ_i MV_i + C w_i = MV_i / V w_c = C / V
q_i 보유수량 · P_i 현재가 · C 현금 · V 총자산
w_i 종목 비중 (현금 포함 분모) · w_c 현금 비중

비중의 분모에 현금을 포함한다. 사용자가 "내 자산에서 삼성전자가 몇 퍼센트"를 물을 때 기대하는 값이기 때문이다. 다만 집중도(HHI) 계산에서는 현금을 제외하고 재정규화한다 — 현금만 늘려도 분산된 것처럼 보이는 왜곡을 막기 위해서다(§3.1).

2.2 평균매입가 — 이동평균법

Moving Average Cost
매수 시 A' = (q × A + q_b × P_b + fee) / (q + q_b) 매도 시 A' = A (수량만 감소, 단가 불변) 평가손익 PnL_i = q_i × (P_i − A_i) 손익률 R_i = P_i / A_i − 1
A 평균매입가 · q_b, P_b 매수 수량·단가 · fee 매수 수수료

국내 증권사 관례인 이동평균법을 따른다. 선입선출(FIFO)을 쓰면 앱의 다른 화면과 손익이 어긋난다. 전량 매도 후 재매수 시 A는 초기화한다.

2.3 수익률 — 외부 현금흐름 조정

Daily / Cumulative Return
r_t = (V_t − F_t) / V_{t-1} − 1 R = Π_t (1 + r_t) − 1
F_t 당일 외부 순입금 (입출금만 포함) · V_t 당일 종가 기준 총자산
흔한 오류

매수·매도는 현금흐름이 아니다. 현금과 주식 사이의 내부 이동이므로 F_t에 넣으면 수익률이 왜곡된다. F_t에 들어가는 것은 사용자가 계좌에 넣거나 뺀 금액뿐이다. 가상 포트폴리오에서는 초기 시드머니 지급과 추가 충전이 여기 해당한다.

§3Risk Engine

3.1 집중도

Concentration
ŵ_i = w_i / (1 − w_c) 주식 내 재정규화 HHI = Σ_i ŵ_i² N_eff = 1 / HHI 유효 종목 수 HHI_sec = Σ_j ( Σ_{i∈j} ŵ_i )² 섹터 집중도 top1 = max_i ŵ_i top3 = Σ (상위 3개 ŵ_i)
ŵ_i 현금 제외 후 비중 · j 섹터 · N_eff 균등 분산으로 환산한 종목 수

N_eff를 함께 계산하는 이유는 설명 가능성 때문이다. HHI 0.28은 사용자에게 아무 의미가 없지만 "사실상 3.6종목에 나눠 담은 것과 같다"는 즉시 이해된다. LLM 프롬프트에는 HHI가 아니라 N_eff를 넣는다.

3.2 변동성

Volatility
σ_i = std(r_i, ddof=1) × √D 개별 종목 연율 변동성 Σ = Cov(R) 일별 수익률 공분산 행렬 σ_p = √(ŵᵀ Σ ŵ) × √D 포트폴리오 연율 변동성 D = 246
R 종목별 일별 수익률 행렬 (60거래일 × N) · ŵ 현금 제외 비중 벡터

포트폴리오 변동성은 개별 변동성의 가중평균이 아니다. 공분산 행렬을 거쳐야 상관관계에 의한 상쇄가 반영된다. 이 차이가 곧 분산효과이며 §3.3에서 지표로 쓴다.

EWMA 대안 — Phase 2 이후

σ²_t = λ σ²_{t-1} + (1 − λ) r²_{t-1} λ = 0.94
최근 변동에 가중. 단순 표준편차는 60일 전 급등락이 60일째 되는 날 갑자기 사라져 지표가 계단식으로 튄다

3.3 상관과 분산효과

Diversification
ρ_ij = Cov(r_i, r_j) / (σ_i σ_j) ρ̄ = Σ_{i≠j} ŵ_i ŵ_j ρ_ij / Σ_{i≠j} ŵ_i ŵ_j 비중가중 평균 상관 DR = ( Σ_i ŵ_i σ_i ) / σ_p 분산 비율
DR ≥ 1 항상 성립 · DR = 1 분산효과 전무 · DR이 클수록 분산이 실제로 작동
기획서의 핵심 주장을 뒷받침하는 지표

"종목은 세 개로 나뉘어 있지만 실질적인 분산 효과는 제한적"이라는 진단은 DR이 근거다. 종목 수나 HHI만으로는 이 주장을 할 수 없다. DR ≤ 1.15이면서 N_eff ≥ 3일 때가 "숫자상 분산, 실질은 집중" 상태이며, 이 조합에서만 해당 문장을 생성하도록 프롬프트에 조건을 건다.

3.4 낙폭과 베타

Drawdown · Beta
peak_t = max_{s ≤ t} V_s DD_t = V_t / peak_t − 1 MDD = min_t DD_t (음수) β = Cov(r_p, r_m) / Var(r_m) 60거래일
r_m 벤치마크 일별 수익률 · 벤치마크는 보유 시장 비중으로 결정 (§4.2)

보유 기간이 60거래일 미만이면 MDD는 계산하되 기간을 함께 표시한다. "최대 낙폭 −8%"만 보여주면 3년치인지 3주치인지 알 수 없다.

Style Tilt
PBR_i = 시가총액_i / 자본총계_i DART 최근 분기 기준 성장 판정 PBR_i ≥ 시장 상위 30% 분위 대형 판정 시가총액 순위 ≤ 100위 w_growth = Σ_{i ∈ 성장} ŵ_i w_large = Σ_{i ∈ 대형} ŵ_i

금리 변화에 대한 회귀 계수를 쓰지 않는다. 국내 금리 변동 이벤트는 연 8회 내외라 60거래일 표본으로는 신뢰할 수 있는 민감도를 추정할 수 없다. 위 값은 섹터 성격에 기반한 근사이며, LLM 프롬프트에 "추정치이며 실제 반응과 다를 수 있음"을 반드시 함께 전달한다. 회귀 기반 전환은 데이터가 2년 이상 쌓인 뒤 검토한다.

§4Attribution Engine

4.1 종목 기여도

Contribution
c_{i,t} = w_{i,t-1} × r_{i,t} r_{p,t} = Σ_i c_{i,t} (현금 수익률 0, w_c 포함해 Σw = 1)
w_{i,t-1} 전일 종가 기준 비중 — 당일 비중을 쓰면 항등식이 깨진다

기여 상위를 contributors, 하위(음수)를 detractors로 내보낸다. 정렬 기준은 수익률이 아니라 기여도다 — 비중 1%인 종목이 20% 올라도 전체에 미치는 영향은 비중 20%인 종목의 1% 상승과 같다.

4.2 시장 · 섹터 · 선택 분해

Brinson–Fachler 모형을 쓴다. 벤치마크는 보유 종목의 시장 구성비로 결정하며, KOSPI·KOSDAQ 혼합 시 비중 가중 합성 지수를 쓴다.

Brinson–Fachler
Allocation_j = (w_j^p − w_j^b) × (r_j^b − r_b) Selection_j = w_j^b × (r_j^p − r_j^b) Interaction_j = (w_j^p − w_j^b) × (r_j^p − r_j^b) Σ_j (A_j + S_j + I_j) = r_p − r_b
w_j^p, w_j^b 섹터 j의 포트폴리오·벤치마크 비중 · r_j^p, r_j^b 섹터 j의 포트폴리오·벤치마크 수익률 · r_b 벤치마크 전체 수익률

API 응답으로의 매핑

breakdown.market = r_b breakdown.sector = Σ_j Allocation_j breakdown.selection = Σ_j ( Selection_j + Interaction_j ) market + sector + selection = r_p ✓ 항등식

Interaction을 selection에 합치는 이유는 사용자에게 3개 이상의 축을 제시하면 이해되지 않기 때문이다. 회계적으로는 별도 항이지만 "종목을 잘 골랐는가"라는 질문에 대한 답으로는 두 항이 같은 방향을 가리킨다.

섹터별 벤치마크 수익률 r_j^b는 KRX 업종지수에서 얻는다. 업종지수가 없는 섹터는 해당 섹터 편입 종목의 시가총액 가중 수익률로 대체하고 proxy: true를 표기한다.

4.3 다기간 연결 — Carino

단순 합산은 틀린다

일별 기여도를 그냥 더하면 총합이 기간 수익률과 맞지 않는다. 복리 효과 때문이며 기간이 길수록 오차가 커진다. 일 변동성 2% 포트폴리오의 40거래일 구간을 시뮬레이션하면 단순 합산 오차가 0.16%p로, 화면에 그대로 노출되는 크기다. 아래 링킹을 적용하면 오차가 부동소수점 한계(1e−15)까지 떨어진다.

Carino Linking
k_t = ln(1 + r_{p,t}) / r_{p,t} r_{p,t} = 0 이면 k_t = 1 K = ln(1 + R_p) / R_p R_p = Π(1 + r_{p,t}) − 1 C_i = Σ_t c_{i,t} × (k_t / K) Σ_i C_i = R_p ✓ 항등식
import numpy as np

def carino_link(daily_contrib, port_returns):
    """daily_contrib: (T, N) 일별 종목 기여도
       port_returns:  (T,)   일별 포트폴리오 수익률"""
    r    = np.asarray(port_returns, dtype=float)
    safe = np.where(np.abs(r) < 1e-12, 1.0, r)          # 0 나눗셈 방지
    k    = np.where(np.abs(r) < 1e-12, 1.0, np.log1p(r) / safe)
    R    = np.prod(1 + r) - 1
    K    = 1.0 if abs(R) < 1e-12 else np.log1p(R) / R
    return (np.asarray(daily_contrib) * (k / K)[:, None]).sum(axis=0)

period=1d는 링킹이 불필요하므로 건너뛴다. 1w 이상에서만 적용한다.

§5Event Intelligence

5.1 이벤트 매칭 신뢰도

Matched Confidence
conf = 0.40 × recency + 0.30 × entity + 0.30 × semantic recency = exp(−Δt / τ) τ = 1 거래일, Δt = 이벤트~변동 간격 entity = 1.0 종목명·종목코드 직접 언급 0.5 섹터·업종 언급 0.3 거시 이벤트 semantic = 임베딩 코사인 유사도 (이벤트 본문 ↔ 변동 방향 문맥)
인과 표현 게이트

conf ≥ 0.60일 때만 LLM에 인과 표현을 허용한다. 미만이면 이벤트를 전달하되 "때문입니다" 대신 "같은 날 다음 소식이 있었습니다" 형태만 쓰도록 프롬프트에서 강제한다. 주가 변동의 원인을 단정하는 것은 이 서비스가 할 수 있는 주장의 범위를 넘는다.

5.2 브리핑 랭킹

Relevance Score
relevance = ŵ_i^0.5 × importance × recency × novelty importance = 1.0 실적 발표 · 실적 정정 0.8 주요 공시 (공급계약 · 유증 · 자사주 · 지분변동) 0.6 거시 이벤트 × rate_sensitivity 계수 0.4 일반 뉴스 0.7 포트폴리오 구조 변화 (섹터 비중 5%p 이상 이동) recency = exp(−days / 2) novelty = 0.3 최근 7일 내 동일 항목 노출 이력 있음 1.0 신규

비중에 제곱근을 씌우는 이유는 선형으로 두면 최대 보유 종목이 상위 4칸을 독식하기 때문이다. 제곱근은 비중을 여전히 반영하되 소액 보유 종목의 중요 이벤트가 올라올 여지를 남긴다.

비용 경계

이 산식은 전부 코드로 계산한다. LLM은 상위 4건이 확정된 뒤 문장 생성에만 호출된다. 랭킹 자체를 LLM에 맡기면 비용이 사용자 수 × 이벤트 수에 비례해 증가하고, 순위 재현성도 사라진다.

결측 처리

  • 거래정지 구간은 직전가 유지가 아니라 해당 날짜를 제외한다. 0 수익률이 들어가면 변동성이 과소 추정된다.
  • 종목 간 거래일이 다르면 교집합으로 정렬한다. 공분산 행렬 계산에는 동일 날짜가 필요하다.
  • 교집합이 60일 미만이면 위 표의 미달 처리를 따른다.
