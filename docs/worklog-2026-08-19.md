## 막혀 있던 것들과 그것을 푼 것

아침에 "데이터가 없어 불가능"으로 판정한 항목이 넷이었다. 저녁에는 전부 열렸다.

### 임베딩 백필 — 무한 루프

`backfill()`은 `embedding IS NULL`인 행을 집는다. 임베딩이 실패하면 그 행은 NULL로
남고 다음 회차가 **같은 행을 다시 집는다.** 끊는 조건이 없어 영원히 돌았다.
2,280건짜리 작업이 20,000건 시도를 찍고 OpenAI 일당 요청 한도를 전부 태웠다.

배치 크기도 문제였다. 계정 한도가 분당 40,000토큰인데 배치 128건은 한 요청이
14만 토큰이라 애초에 통과할 수 없었다.

429를 맞고 물러나는 것만으로는 부족했다 — **429도 일당 요청 한도를 깎아서,
재시도할수록 다음 실행이 불리해진다.** 그래서 응답 헤더의 잔량을 보고 미리 쉬고,
비용 어림은 응답의 `usage.prompt_tokens`로 문자당 토큰(한글 ≈ 0.7)을 학습시켰다.
이후 429는 사라졌고 남은 2,190건이 3분에 끝났다.

### 시세 — 적재기는 있었지만 돌린 적이 없었다

Risk Engine 워커를 띄우기 직전에 `price_daily`가 0행인 것을 발견했다. 산식이
요구하는 것은 실시간 호가가 아니라 **일별 종가 시계열**이다.

시총 상위 200종목으로 한정하려 했으나 불가능했다. pykrx의 횡단면 엔드포인트가
전부 KRX 로그인을 요구해 `market_cap`이 2,596종목 전부 NULL이었기 때문이다.
그런데 실측해 보니 종목당 0.02초라 **전 종목이 11분**이면 끝났다. 선별 문제가
사라지는 쪽을 택했다.

### 지수와 시가총액 — KRX OpenAPI

베타(§3.4)와 스타일 틸트(§3.5)가 여기서 막혔다. pykrx 지수 API는 로그인 없이
죽어 있고 `ECOS_API_KEY`도 없었다.

KRX OpenAPI 키를 받고도 한동안 401이 났다. **대조군을 넣어 원인을 갈랐다** —
가짜 키는 `Unauthorized Key`, 실제 키는 `Unauthorized API Call`. 메시지가 다르니
키는 인식되는 것이고, 남은 것은 서비스 이용 승인뿐이었다. 승인 후 지수·유가증권·
코스닥이 한꺼번에 열렸다.

### 자본총계 — DART

`w_growth`는 PBR = 시가총액 / 자본총계인데 자본총계를 담은 곳이 없었다.
`get_financials`가 DART 호출이라고 잘못 알고 있었으나 실은 공시 코퍼스를 검색하는
RAG 별칭이었다. 재무 테이블을 새로 만들고 DART `fnlttSinglAcnt`로 채웠다.

### 응답 로그 — 하나가 둘을 막고 있었다

`feedback.py`는 "응답 로그 저장소가 아직 연결되지 않았습니다"만 던지는 스텁이었다.
파보니 `ai_responses`에 행을 쓰는 코드가 없어서 **두 가지가 같은 이유로** 막혀
있었다.

| 막힌 것 | 이유 |

| 피드백 (§10) | `ai_feedback.request_id`가 `ai_responses`를 외래키로 참조 |

두 번째는 Portfolio Doctor를 만든 워커가 `portfolio.py`에 `previous_level=None`으로
두고 "빠뜨린 게 아니라 미룬 것"이라고 적어 둔 자리다. 응답 로그 하나로 둘 다 풀렸다.

## 판단과 그 이유

**LLM 공급자에 본가를 두지 않았다.** `OpenAIClient`와 `AnthropicClient`는 같은
계약의 두 구현이고 `LLM_PROVIDER`로 고른다. 도구 루프가 주고받는 메시지는
Anthropic 표기를 따르되, 표기와 각 API 사이의 번역은 클라이언트 안에서 끝냈다 —
루프를 공급자 수만큼 분기시키지 않기 위해서다.

**측정으로 이득이 확인되지 않은 변경은 되돌렸다.** 검색이 놓친 케이스를 보고
문서당 조각 수 상한을 의심해 구현까지 했으나, 1·2·무제한 셋 다 Recall@5가 0.875로
같았다. 되돌리고 측정 결과를 `eval/retrieval.yaml`에 남겼다. 그 실패의 진짜 원인은
밀집 검색의 어휘 약점이고, 해법은 하이브리드 검색(tsvector + 벡터)이다.

**베타를 Risk Score에 넣지 않았다.** §3.6은 다섯 항목을 가중하며 베타는 그중에
없다. 넣으면 기존 점수 테스트가 전부 틀어지고 명세와도 어긋난다.

**Before You Trade에 별도 엔진을 두지 않았다.** 주문 전 점검은 진단 엔진을 두 번
호출한 차분이다. `app/engines/`는 한 줄도 바뀌지 않았다.

**Attribution의 벤치마크는 자체 계산으로 갔다.** KRX 섹터지수 24종을 쓸 수도
있었지만 그 어휘(전기전자, 금융…)가 `ingest/ksic_sectors.json`(반도체,
IT하드웨어, 은행…)과 다르다. 반도체와 IT하드웨어가 둘 다 전기전자에 뭉개진다.
시총가중으로 직접 계산하면 어휘가 포트폴리오 쪽과 그대로 일치한다.

**피드백은 없는 `request_id`와 남의 것에 같은 오류를 준다.** 구분해 주면 id를
하나씩 찔러 존재 여부를 알아낼 수 있다.

## 두 번 겪지 않을 것들

**워커에게 참고 파일을 가리키지 말 것.** 같은 태스크를 두 번 돌려 확인했다.
"`stocks.py`를 본으로 삼아라"로 보낸 워커는 그 파일만 반복해 읽다 중단됐고(산출물
0), 라우트 골격과 import 목록을 붙여 넣은 재시도는 커밋 2건과 PR로 끝났다.
파일을 가리키는 것은 답이 아니라 숙제를 주는 것이다. 붙여 넣는 것만으로도 부족해서
**"이 파일은 읽지 않아도 된다"**를 함께 적어야 한다. `docs/worker-task-template.md`
의 `[PATTERN]` 절이 여기서 나왔다.

**병렬로 띄울 때는 스키마 소유권을 한 워커에만.** `models.py`와 `alembic/`을 둘
이상이 건드리면 마이그레이션 head가 갈라진다. W12에 명시적으로 위임하고 W13에
명시적으로 금지한 결과, head는 하나로 유지됐고 두 PR의 변경 파일이 하나도 겹치지
않았다.

**적재 태스크의 완료 보고에 채우지 못한 건수를 요구할 것.** "적재 완료"는 0행
적재와 구분되지 않는다. 성공만 세면 커버리지가 99%인지 5%인지 알 수 없다.

**증분 루프에는 반드시 진척 없음 조건을 둘 것.** 백필 무한 루프가 그 교훈이다.
