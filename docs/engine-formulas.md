# 엔진 산식 명세

AI 응답에 등장하는 모든 수치의 계산 근거를 정의한다. LLM은 이 문서의 출력값을 설명할 뿐 어떤 값도 스스로 만들지 않는다.

**시장** KOSPI · KOSDAQ · **통화** KRW 단일 · **주기** 일별 종가 · **연환산** 246 거래일

## §1 공통 기준

모든 엔진은 아래 기준을 공유한다. 엔진마다 다른 기준을 쓰면 화면 간 수치가 어긋나므로 **여기서 벗어나는 계산은 허용하지 않는다.**

| 항목 | 기준 | 근거 |
| --- | --- | --- |
| 수익률 형태 | 산술 수익률 `P_t/P_{t-1} − 1` | 기여도 합산이 성립하려면 로그수익률을 쓸 수 없다 |
| 가격 | 수정주가 종가 | 액면분할·유상증자 왜곡 제거. pykrx 수정주가 사용 |
| 연환산 거래일 | `D = 246` | 국내 증시 연간 개장일 실측치. 252는 미국 기준이라 쓰지 않는다 |
| 표본 표준편차 | `ddof = 1` | 모표준편차가 아닌 표본 추정 |
| 관측 구간 | 기본 60거래일 | 상관·변동성 추정의 최소 표본. §6 참조 |
| 휴장일 | 거래일 인덱스로 정렬 후 계산 | 달력일 기준으로 하면 주말이 0 수익률로 들어간다 |
| 배당 | Phase 1 제외 | 가격 수익률만. 총수익률은 Phase 3 이후 |

## §2 Portfolio Engine

### 2.1 평가금액과 비중

**Valuation**

```
MV_i = q_i × P_i
V    = Σ_i MV_i + C
w_i  = MV_i / V
w_c  = C / V
```
> **q_i** 보유수량 · **P_i** 현재가 · **C** 현금 · **V** 총자산 
 **w_i** 종목 비중 (현금 포함 분모) · **w_c** 현금 비중

비중의 분모에 현금을 포함한다. 사용자가 "내 자산에서 삼성전자가 몇 퍼센트"를 물을 때 기대하는 값이기 때문이다. **다만 집중도(HHI) 계산에서는 현금을 제외하고 재정규화한다** — 현금만 늘려도 분산된 것처럼 보이는 왜곡을 막기 위해서다([§3.1](#rk-conc)).

### 2.2 평균매입가 — 이동평균법

**Moving Average Cost**

```
매수 시   A' = (q × A + q_b × P_b + fee) / (q + q_b)
매도 시   A' = A                    (수량만 감소, 단가 불변)
평가손익  PnL_i = q_i × (P_i − A_i)
손익률    R_i   = P_i / A_i − 1
```
> **A** 평균매입가 · **q_b, P_b** 매수 수량·단가 · **fee** 매수 수수료

국내 증권사 관례인 이동평균법을 따른다. 선입선출(FIFO)을 쓰면 앱의 다른 화면과 손익이 어긋난다. 전량 매도 후 재매수 시 `A`는 초기화한다.

### 2.3 수익률 — 외부 현금흐름 조정

**Daily / Cumulative Return**

```
r_t = (V_t − F_t) / V_{t-1} − 1
R   = Π_t (1 + r_t) − 1
```
> **F_t** 당일 *외부* 순입금 (입출금만 포함) · **V_t** 당일 종가 기준 총자산

> **흔한 오류**
> **매수·매도는 현금흐름이 아니다.** 현금과 주식 사이의 내부 이동이므로 `F_t`에 넣으면 수익률이 왜곡된다. `F_t`에 들어가는 것은 사용자가 계좌에 넣거나 뺀 금액뿐이다. 가상 포트폴리오에서는 초기 시드머니 지급과 추가 충전이 여기 해당한다.

## §3 Risk Engine

### 3.1 집중도

**Concentration**

```
ŵ_i     = w_i / (1 − w_c)          주식 내 재정규화
HHI     = Σ_i ŵ_i²
N_eff   = 1 / HHI                   유효 종목 수
HHI_sec = Σ_j ( Σ_{i∈j} ŵ_i )²      섹터 집중도
top1    = max_i ŵ_i
top3    = Σ (상위 3개 ŵ_i)
```
> **ŵ_i** 현금 제외 후 비중 · **j** 섹터 · **N_eff** 균등 분산으로 환산한 종목 수

`N_eff`를 함께 계산하는 이유는 설명 가능성 때문이다. HHI 0.28은 사용자에게 아무 의미가 없지만 "사실상 3.6종목에 나눠 담은 것과 같다"는 즉시 이해된다. **LLM 프롬프트에는 HHI가 아니라 `N_eff`를 넣는다.**

### 3.2 변동성

**Volatility**

```
σ_i  = std(r_i, ddof=1) × √D          개별 종목 연율 변동성
Σ    = Cov(R)                         일별 수익률 공분산 행렬
σ_p  = √(ŵᵀ Σ ŵ) × √D                포트폴리오 연율 변동성
D    = 246
```
> **R** 종목별 일별 수익률 행렬 (60거래일 × N) · **ŵ** 현금 제외 비중 벡터

포트폴리오 변동성은 개별 변동성의 가중평균이 *아니다.* 공분산 행렬을 거쳐야 상관관계에 의한 상쇄가 반영된다. 이 차이가 곧 분산효과이며 [§3.3](#rk-corr)에서 지표로 쓴다.

#### EWMA 대안 — Phase 2 이후

```
σ²_t = λ σ²_{t-1} + (1 − λ) r²_{t-1}      λ = 0.94
```
> 최근 변동에 가중. 단순 표준편차는 60일 전 급등락이 60일째 되는 날 갑자기 사라져 지표가 계단식으로 튄다

### 3.3 상관과 분산효과

**Diversification**

```
ρ_ij = Cov(r_i, r_j) / (σ_i σ_j)

ρ̄    = Σ_{i≠j} ŵ_i ŵ_j ρ_ij  /  Σ_{i≠j} ŵ_i ŵ_j     비중가중 평균 상관

DR   = ( Σ_i ŵ_i σ_i ) / σ_p                          분산 비율
```
> **DR ≥ 1** 항상 성립 · **DR = 1** 분산효과 전무 · **DR**이 클수록 분산이 실제로 작동

> **기획서의 핵심 주장을 뒷받침하는 지표**
> "종목은 세 개로 나뉘어 있지만 실질적인 분산 효과는 제한적"이라는 진단은 `DR`이 근거다. 종목 수나 HHI만으로는 이 주장을 할 수 없다. **`DR ≤ 1.15`이면서 `N_eff ≥ 3`일 때가 "숫자상 분산, 실질은 집중" 상태**이며, 이 조합에서만 해당 문장을 생성하도록 프롬프트에 조건을 건다.

### 3.4 낙폭과 베타

**Drawdown · Beta**

```
peak_t = max_{s ≤ t} V_s
DD_t   = V_t / peak_t − 1
MDD    = min_t DD_t                     (음수)

β = Cov(r_p, r_m) / Var(r_m)            60거래일
```
> **r_m** 벤치마크 일별 수익률 · 벤치마크는 보유 시장 비중으로 결정 ([§4.2](#at-brinson))

보유 기간이 60거래일 미만이면 `MDD`는 계산하되 **기간을 함께 표시**한다. "최대 낙폭 −8%"만 보여주면 3년치인지 3주치인지 알 수 없다.

### 3.5 스타일 편중과 금리민감도

**Style Tilt**

```
PBR_i = 시가총액_i / 자본총계_i          DART 최근 분기 기준
성장 판정  PBR_i ≥ 시장 상위 30% 분위
대형 판정  시가총액 순위 ≤ 100위

w_growth = Σ_{i ∈ 성장} ŵ_i
w_large  = Σ_{i ∈ 대형} ŵ_i
```
> 분위 기준은 매 분기 재계산하며 계산 시점을 `as_of`로 기록한다

#### 금리민감도 — 규칙 기반 프록시

```
S = Σ_i ŵ_i × s(sector_i)

s(sector) = +1.0  반도체 · IT · 바이오 · 2차전지 · 인터넷
            +0.3  경기소비재 · 산업재
             0.0  통신 · 유틸리티 · 필수소비재
            −0.5  은행 · 보험 · 증권

rate_sensitivity = high      S ≥ 0.60
                   moderate  0.25 ≤ S < 0.60
                   low       S < 0.25
```

> **한계 명시**
> 금리 변화에 대한 **회귀 계수를 쓰지 않는다.** 국내 금리 변동 이벤트는 연 8회 내외라 60거래일 표본으로는 신뢰할 수 있는 민감도를 추정할 수 없다. 위 값은 섹터 성격에 기반한 근사이며, **LLM 프롬프트에 "추정치이며 실제 반응과 다를 수 있음"을 반드시 함께 전달한다.** 회귀 기반 전환은 데이터가 2년 이상 쌓인 뒤 검토한다.

### 3.6 Risk Score

각 지표를 0–100으로 정규화한 뒤 가중 합산한다. 정규화는 구간 선형이며 범위를 벗어나면 절단한다.

**Normalization**

```
s(x; lo, hi) = clip( (x − lo) / (hi − lo), 0, 1 ) × 100

risk_score = Σ_k ( weight_k × s_k ) / 100        0 ≤ score ≤ 100
```

| 구성요소 | 지표 | lo → 0점 | hi → 100점 | 가중 |
| --- | --- | --- | --- | --- |
| 종목 집중도 | `HHI` | 0.10 | 0.50 | 30 |
| 섹터 집중도 | `HHI_sec` | 0.20 | 0.60 | 25 |
| 변동성 | `σ_p` | 0.15 | 0.45 | 20 |
| 분산 실패 | `DR` (역방향) | 1.50 | 1.05 | 15 |
| 현금 완충 부족 | `w_c` (역방향) | 0.20 | 0.02 | 10 |

역방향 지표는 `lo > hi`로 두면 같은 식이 그대로 성립한다. 가중치 합은 100이다.

**Risk Level**

```
low       score < 35
moderate  35 ≤ score < 65
high      score ≥ 65
```

> **경계 안정화**
> 임계값 근처에서 등급이 매일 뒤집히면 신뢰를 잃는다. **등급 변경은 이전 등급 대비 ±3점 이상 벌어졌을 때만 반영**하는 히스테리시스를 적용한다. 예를 들어 `moderate`에서 `high`로 올라가려면 68점 이상이어야 하고, 내려오려면 62점 이하여야 한다.

## §4 Attribution Engine

### 4.1 종목 기여도

**Contribution**

```
c_{i,t} = w_{i,t-1} × r_{i,t}

r_{p,t} = Σ_i c_{i,t}      (현금 수익률 0, w_c 포함해 Σw = 1)
```
> **w_{i,t-1}** *전일 종가 기준* 비중 — 당일 비중을 쓰면 항등식이 깨진다

기여 상위를 `contributors`, 하위(음수)를 `detractors`로 내보낸다. 정렬 기준은 수익률이 아니라 **기여도**다 — 비중 1%인 종목이 20% 올라도 전체에 미치는 영향은 비중 20%인 종목의 1% 상승과 같다.

### 4.2 시장 · 섹터 · 선택 분해

Brinson–Fachler 모형을 쓴다. 벤치마크는 보유 종목의 시장 구성비로 결정하며, KOSPI·KOSDAQ 혼합 시 비중 가중 합성 지수를 쓴다.

**Brinson–Fachler**

```
Allocation_j  = (w_j^p − w_j^b) × (r_j^b − r_b)
Selection_j   =  w_j^b        × (r_j^p − r_j^b)
Interaction_j = (w_j^p − w_j^b) × (r_j^p − r_j^b)

Σ_j (A_j + S_j + I_j) = r_p − r_b
```
> **w_j^p, w_j^b** 섹터 j의 포트폴리오·벤치마크 비중 · **r_j^p, r_j^b** 섹터 j의 포트폴리오·벤치마크 수익률 · **r_b** 벤치마크 전체 수익률

#### API 응답으로의 매핑

```
breakdown.market    = r_b
breakdown.sector    = Σ_j Allocation_j
breakdown.selection = Σ_j ( Selection_j + Interaction_j )

market + sector + selection = r_p            ✓ 항등식
```

Interaction을 selection에 합치는 이유는 사용자에게 3개 이상의 축을 제시하면 이해되지 않기 때문이다. 회계적으로는 별도 항이지만 **"종목을 잘 골랐는가"라는 질문에 대한 답으로는 두 항이 같은 방향**을 가리킨다.

섹터별 벤치마크 수익률 `r_j^b`는 KRX 업종지수에서 얻는다. 업종지수가 없는 섹터는 해당 섹터 편입 종목의 시가총액 가중 수익률로 대체하고 `proxy: true`를 표기한다.

### 4.3 다기간 연결 — Carino

> **단순 합산은 틀린다**
> 일별 기여도를 그냥 더하면 총합이 기간 수익률과 맞지 않는다. 복리 효과 때문이며 기간이 길수록 오차가 커진다. **일 변동성 2% 포트폴리오의 40거래일 구간을 시뮬레이션하면 단순 합산 오차가 0.16%p**로, 화면에 그대로 노출되는 크기다. 아래 링킹을 적용하면 오차가 부동소수점 한계(1e−15)까지 떨어진다.

**Carino Linking**

```
k_t = ln(1 + r_{p,t}) / r_{p,t}          r_{p,t} = 0 이면 k_t = 1
K   = ln(1 + R_p)   / R_p               R_p = Π(1 + r_{p,t}) − 1

C_i = Σ_t c_{i,t} × (k_t / K)

Σ_i C_i = R_p                            ✓ 항등식
```

```
import numpy as np

def carino_link(daily_contrib, port_returns):
    """daily_contrib: (T, N) 일별 종목 기여도
       port_returns:  (T,)   일별 포트폴리오 수익률"""
    r    = np.asarray(port_returns, dtype=float)
    safe = np.where(np.abs(r) < 1e-12, 1.0, r)          # 0 나눗셈 방지
    k    = np.where(np.abs(r) < 1e-12, 1.0, np.log1p(r) / safe)
    R    = np.prod(1 + r) - 1
    K    = 1.0 if abs(R) < 1e-12 else np.log1p(R) / R
    return (np.asarray(daily_contrib) * (k / K)[:, None]).sum(axis=0)
```

`period=1d`는 링킹이 불필요하므로 건너뛴다. `1w` 이상에서만 적용한다.

## §5 Event Intelligence

### 5.1 이벤트 매칭 신뢰도

**Matched Confidence**

```
conf = 0.40 × recency + 0.30 × entity + 0.30 × semantic

recency  = exp(−Δt / τ)          τ = 1 거래일, Δt = 이벤트~변동 간격
entity   = 1.0  종목명·종목코드 직접 언급
           0.5  섹터·업종 언급
           0.3  거시 이벤트
semantic = 임베딩 코사인 유사도 (이벤트 본문 ↔ 변동 방향 문맥)
```

> **인과 표현 게이트**
> `conf ≥ 0.60`일 때만 LLM에 인과 표현을 허용한다. 미만이면 이벤트를 전달하되 **"때문입니다" 대신 "같은 날 다음 소식이 있었습니다"** 형태만 쓰도록 프롬프트에서 강제한다. 주가 변동의 원인을 단정하는 것은 이 서비스가 할 수 있는 주장의 범위를 넘는다.

### 5.2 브리핑 랭킹

**Relevance Score**

```
relevance = ŵ_i^0.5 × importance × recency × novelty

importance = 1.0  실적 발표 · 실적 정정
             0.8  주요 공시 (공급계약 · 유증 · 자사주 · 지분변동)
             0.6  거시 이벤트 × rate_sensitivity 계수
             0.4  일반 뉴스
             0.7  포트폴리오 구조 변화 (섹터 비중 5%p 이상 이동)

recency = exp(−days / 2)
novelty = 0.3   최근 7일 내 동일 항목 노출 이력 있음
          1.0   신규
```

비중에 **제곱근을 씌우는 이유**는 선형으로 두면 최대 보유 종목이 상위 4칸을 독식하기 때문이다. 제곱근은 비중을 여전히 반영하되 소액 보유 종목의 중요 이벤트가 올라올 여지를 남긴다.

> **비용 경계**
> 이 산식은 **전부 코드로 계산한다.** LLM은 상위 4건이 확정된 뒤 문장 생성에만 호출된다. 랭킹 자체를 LLM에 맡기면 비용이 사용자 수 × 이벤트 수에 비례해 증가하고, 순위 재현성도 사라진다.

## §6 운영 규칙

### 6.1 결측과 최소 데이터 요건

| 지표 | 최소 거래일 | 미달 시 동작 |
| --- | --- | --- |
| 비중 · 평가손익 | 0 | 항상 계산 가능 |
| HHI · 집중도 | 0 | 항상 계산 가능 |
| 일별 기여도 | 2 | `INSUFFICIENT_DATA` |
| 변동성 · MDD | 60 | 지표 `null`, Risk Score에서 해당 항목 제외 후 가중 재정규화 |
| 상관 · DR · 베타 | 60 | 동일 |
| Brinson 분해 | 2 | `INSUFFICIENT_DATA` |

신규 상장 종목이 섞이면 그 종목만 히스토리가 짧다. 이때 **전체를 포기하지 않고 해당 종목을 제외한 부분집합으로 계산**하되, 제외 비중이 20%를 넘으면 지표를 `null`로 낸다. 응답에는 항상 `coverage`(계산에 포함된 비중)를 함께 실어 LLM이 한계를 언급할 수 있게 한다.

#### 결측 처리

- 거래정지 구간은 **직전가 유지가 아니라 해당 날짜를 제외**한다. 0 수익률이 들어가면 변동성이 과소 추정된다.
- 종목 간 거래일이 다르면 **교집합**으로 정렬한다. 공분산 행렬 계산에는 동일 날짜가 필요하다.
- 교집합이 60일 미만이면 위 표의 미달 처리를 따른다.

### 6.2 정밀도 정책

| 단계 | 규칙 |
| --- | --- |
| 내부 계산 | `float64` 전 구간 유지. 중간 반올림 금지 |
| API `raw` | 반올림하지 않은 원값 그대로 |
| 표시 — 비율 | 소수 1자리, **half-up** (은행가 반올림 아님) |
| 표시 — 금액 | 정수 원. 1억 이상은 "1억 2,340만 원" 형태로 축약 |
| 표시 — 기여도 | `%p` 단위 소수 2자리. 합이 총합과 어긋나면 최대 항목에서 잔차 흡수 |
| 0 근처 | `\|x\| < 0.00005`는 `0.0%`로 표시하되 부호를 붙이지 않는다 |

기여도 표시에서 **잔차를 최대 항목에 흡수시키는 처리**가 필요하다. 각 항목을 독립적으로 반올림하면 합계가 총 수익률과 0.01%p 어긋나 보이고, 사용자는 이를 계산 오류로 받아들인다.

### 6.3 검증 항등식

아래는 단위 테스트로 상시 검증한다. 하나라도 깨지면 응답을 내보내지 않는다.

| # | 항등식 | 허용 오차 |
| --- | --- | --- |
| 1 | `Σ w_i + w_c = 1` | 1e−9 |
| 2 | `Σ ŵ_i = 1` | 1e−9 |
| 3 | `Σ c_i,t = r_p,t` (일별) | 1e−9 |
| 4 | `Σ C_i = R_p` (Carino 적용 후) | 1e−6 |
| 5 | `market + sector + selection = r_p` | 1e−9 |
| 6 | `1/N ≤ HHI ≤ 1` | — |
| 7 | `DR ≥ 1` | 1e−9 |
| 8 | `0 ≤ risk_score ≤ 100` | — |
| 9 | `MDD ≤ 0` | — |

> **응답 대조 검증**
> API 명세 §2.3의 마지막 검사는 이 문서와 맞물린다. **응답의 `segments[].raw`가 엔진 출력과 일치하는지** 반환 직전에 대조한다. 항등식 검증이 엔진 내부의 정합성을 보장한다면, 이 대조는 엔진과 LLM 사이에서 값이 변질되지 않았음을 보장한다. 두 층이 모두 있어야 숫자 정확도가 성립한다.

#### 골든 케이스

손으로 검산 가능한 고정 포트폴리오를 회귀 테스트로 고정한다. 최소 4종.

1. **단일 종목** — `HHI = 1`, `N_eff = 1`, `DR = 1`, 기여도 = 수익률
2. **균등 2종목 · 무상관** — `HHI = 0.5`, `DR = √2 ≈ 1.414`
3. **완전 상관 3종목** — `DR = 1`. 분산 실패 판정이 나와야 함
4. **기간 중 입금 발생** — 수익률이 입금액에 영향받지 않아야 함 ([§2.3](#pf-return))
