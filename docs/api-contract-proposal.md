# AI 서비스 API 계약 — 0-5 협의용 제안

> **이 문서는 제안이지 확정이 아닙니다.**
> AI 서비스가 **이미 구현해 운영 중인** 규약을 그대로 정리한 것입니다.
> 0-5 공통 API 규격(FINCH-23)이 다르게 확정되면 AI 파트가 맞춥니다.
> 백지에서 설계하는 대신 이걸 놓고 고치는 편이 빠를 것 같아 먼저 올립니다.
>
> 관련: FINCH-70 · 선행 대상 FINCH-23 · 후속 FINCH-30

featureSpec 의 AI MVP 3종이 어느 엔드포인트인지입니다. 별도 엔드포인트를 새로 만들지 않았습니다.

| featureSpec §10.2 | 엔드포인트 | 비고 |
|---|---|---|
| 종목 분석 | `POST /stocks/{ticker}/analysis` | 7개 섹션. `sections` 로 골라 받습니다 |
| 용어 설명 | `POST /chat` | 투자 용어 질의는 대화 에이전트가 답합니다. 도구 없이 답하므로 `tools_used` 가 빈 배열입니다 |
| 보유 종목 요약 | `POST /portfolio/diagnosis` | |

**용어 설명 전용 엔드포인트는 만들지 않습니다.** 용어 질의와 "내 삼성전자 어때?" 를 프런트가 미리 갈라내야 하는데, 그 분류를 프런트에 떠넘기는 셈이라 한 창구로 받습니다.

### 1.2 SSE 는 아직 없습니다

`api-spec.md` §2.5 에 SSE 스트리밍 규약이 적혀 있지만 **구현되어 있지 않습니다.** `Accept` 와 무관하게 §2 의 JSON 봉투를 한 번에 돌려줍니다. `openapi.json` 에도 스트리밍 응답은 없습니다. 프런트가 §2.5 를 보고 `EventSource` 를 붙이면 동작하지 않으므로 해당 절에 미구현 표시를 달아 두었습니다.

## 2. 성공 응답 봉투

모든 성공 응답은 아래 봉투로 감쌉니다. `content` 만 엔드포인트마다 다릅니다.

```json
{
  "request_id": "...",
  "generated_at": "2026-08-20T14:30:00+09:00",
  "data_as_of": { "price": "...", "news": "...", "macro": "..." },
  "model": "gpt-5.4-mini",
  "cached": false,
  "content": { },
  "citations": [],
  "disclaimer": "투자 판단의 최종 책임은 본인에게 있습니다."
}
```

| 필드 | 이유 |
|---|---|
| `request_id` | 장애 추적. 에러 응답에도 동일 필드가 있어 짝을 맞춥니다 |
| `data_as_of` | **금융 서비스라 필수입니다.** 시세·뉴스·거시 지표의 기준 시각이 다르고, 화면에 "몇 시 기준"을 못 쓰면 오해를 삽니다 |
| `model` · `cached` | 같은 질문에 다른 답이 나올 때 원인 구분용 |
| `citations` | 근거 표시. 없으면 LLM 출력이 사실처럼 보입니다 |
| `disclaimer` | 투자 자문 회피 문구. 응답마다 실려야 합니다 |

**백엔드가 그대로 프록시할지, 벗겨서 팀 공통 봉투로 다시 감쌀지 정해주셔야 합니다.**
벗기신다면 `data_as_of` · `citations` · `disclaimer` 는 어떤 형태로든 프런트까지 전달되어야 합니다.

## 3. 에러 응답 — **백엔드 §1.3 형식으로 맞췄습니다**

```json
{
  "code": "LLM_TIMEOUT",
  "message": "응답이 지연되어 중단했습니다. 다시 시도해 주세요.",
  "detail": {},
  "request_id": "req_01JQZ8M3T7K2"
}
```

전에는 `error` 로 한 겹 감쌌는데 벗겼습니다. 백엔드가 매핑 코드를 만드는 것보다 우리가 맞추는 편이 쌉니다.

- `message` 는 **사용자에게 그대로 보여도 되는 한국어 문구**입니다. §1.3 대로 그대로 노출하셔도 됩니다. "LLM 키가 없습니다" 같은 내부 사정은 담지 않았고, 기계가 분기할 사유는 `detail.reason` 으로 보냅니다 (`llm_key_missing` · `ledger_unavailable` · `internal_token_mismatch` 등).
- **`request_id` 는 §1.3 에 없지만 최상위에 남겼습니다.** `POST /feedback` 이 이 값으로 응답을 찾습니다. 에러에서만 빠지면 "이 답변 이상해요" 를 응답에 맞출 수 없습니다. 빼야 한다면 말씀해 주세요.
- **필드 명명은 아직 snake_case 입니다.** `request_id` 는 성공 봉투에도 있는 같은 필드인데, 봉투가 §1.3 회신 대기라 지금 에러만 `requestId` 로 바꾸면 한 개념이 한 API 안에서 두 이름이 됩니다. 봉투 회신이 오면 직렬화 지점 한 곳에서 둘을 함께 바꿉니다.

### 에러 코드와 HTTP 상태

`app/core/errors.py` 의 `STATUS_BY_CODE` 그대로입니다.

| 코드 | 상태 | 발생 상황 |
|---|---|---|
| `INVALID_REQUEST` | 400 | 요청 형식 오류 |
| `UNSUPPORTED_MARKET` | 400 | 해외 종목 요청 (국내 주식 전용) |
| `UNAUTHORIZED` | 401 | 인증 실패 |
| `INSTRUMENT_NOT_FOUND` | 404 | 없는 종목 |
| `INSUFFICIENT_DATA` | 409 | 분석에 필요한 데이터 부족 |
| `GUARDRAIL_BLOCKED` | 422 | 출력 가드레일 차단 |
| `RATE_LIMITED` | 429 | 호출 한도 초과 |
| `RETRIEVAL_FAILED` | 502 | 근거 검색 실패 |
| `LLM_TIMEOUT` | 504 | LLM 응답 시간 초과 |

HTTP 상태는 `errors.py` 한 곳에서만 결정하고 라우터가 직접 지정하지 않습니다.

### 프런트가 다르게 다뤄야 하는 것들

아래 넷은 "그냥 실패"가 아니라 **화면에서 다른 문구가 나가야 합니다.** 뭉뚱그리면 사용자가 재시도할지 포기할지 판단할 수 없습니다.

| 코드 | 프런트 처리 |
|---|---|
| `INSUFFICIENT_DATA` | 재시도해도 소용없음 — 데이터가 쌓여야 함을 안내 |
| `GUARDRAIL_BLOCKED` | 답변 거부. 재시도 유도하지 않음 |
| `LLM_TIMEOUT` | 재시도 가능 |
| `RETRIEVAL_FAILED` | 근거 없이 답할 수 없음. 재시도 가능 |

### "근거 없음" 은 에러가 아닙니다

헷갈리기 쉬운 부분이라 못 박아 둡니다.

| 상황 | 응답 | 프런트 |
|---|---|---|
| 검색은 됐는데 맞는 자료가 없음 | **200** — 본문에 "관련 자료를 찾지 못했습니다" | 그대로 출력. 재시도 무의미 |
| 검색 자체가 고장남 | **502 `RETRIEVAL_FAILED`** | 재시도 버튼 |
| 엔진 계산에 필요한 데이터 부족 | **409 `INSUFFICIENT_DATA`** | AI 영역만 비활성. 화면 전체 실패 아님 |

둘을 같은 화면으로 처리하면 검색이 죽어 있는 동안 사용자는 "자료가 없구나" 하고 넘어갑니다. `INSUFFICIENT_DATA` 도 화면 전체를 실패로 다루면 안 됩니다 — 신규 가입자는 보유 종목이 없는 게 정상입니다.

이게 3-4(FINCH-56)의 본체이므로 코드 체계가 바뀌면 그쪽도 같이 바뀝니다.

## 4. 인증 — **확정**

호출 경로는 **프런트 → 백엔드 → AI** 입니다. 백엔드가 이미 JWT 를 검증하므로 AI 가 다시 검증하면 서명 키를 두 곳에서 관리하게 됩니다. 그래서 **백엔드가 검증 후 신뢰된 사용자 식별자를 헤더로 넘기는** 쪽으로 정했고, 백엔드 API 명세 §9 의 헤더 두 개를 그대로 받습니다.

```
X-Internal-Token: <서비스 간 공유 토큰>
X-User-Id: <사용자 식별자>
```

| 항목 | 값 |
|---|---|
| `X-Internal-Token` | 호출자가 백엔드인지 확인. `BACKEND_SERVICE_TOKEN` 과 대조합니다 |
| `X-User-Id` | 사용자 식별자 문자열. 앞뒤 공백은 잘라냅니다 |
| 헤더 이름 변경 | `INTERNAL_TOKEN_HEADER` · `TRUSTED_USER_HEADER` 로 바꿉니다 |
| 하나라도 틀리면 | `UNAUTHORIZED` (401) |
| `Authorization` | **AI 는 읽지 않습니다.** 백엔드에서 끝납니다 |

토큰 비교는 `hmac.compare_digest` 로 합니다. `==` 는 앞에서부터 다른 자리를 찾다가 멈춰서, 걸린 시간이 토큰을 한 글자씩 알려줍니다.

`BACKEND_SERVICE_TOKEN` 이 비어 있으면 **`APP_ENV=local` 에서만** 토큰 검증을 건너뜁니다. 운영에서 비워 두는 것은 설정 사고이므로 401 로 막습니다 — 그때 열어 두면 인증이 아예 없는 것과 같습니다.

구현은 `app/api/deps.py` 의 `get_current_user_id` 이고, `docs/openapi.json` 에는 `internalToken` · `trustedUserHeader` 두 시큐리티 스킴으로 실려 있습니다(한 객체 안에 둘 = AND).

### ⚠️ 배포 조건 — **AI 서버는 외부에 노출되면 안 됩니다**

AI 서버는 `X-User-Id` 를 **검증 없이 그대로 신뢰합니다.** 외부에서 직접 닿을 수 있으면 누구나 헤더를 위조해 남의 위키·포트폴리오·피드백을 읽습니다.

- AI 서버는 **내부 네트워크에서만** 접근 가능해야 합니다. 공인 IP·인그레스·포트 포워딩을 열지 않습니다.
- 외부 트래픽은 **백엔드를 반드시 거쳐야** 하며, 백엔드는 클라이언트가 보낸 `X-User-Id` 를 **덮어씁니다** (전달하지 않고 자기가 검증한 값으로 새로 씁니다).
- 팀 API 명세의 `/internal/v1` 이 "AI 서버 전용, 외부 비공개" 인 것과 같은 원칙이며, 방향만 반대입니다.

이 조건이 깨지면 인증이 없는 것과 같습니다. 인프라 담당자와 함께 확인해 주세요.

### 백엔드가 다른 방식을 원하신다면

헤더 이름만 다르면 `TRUSTED_USER_HEADER` 한 줄입니다. AI 가 JWT 를 직접 검증하는 쪽으로 뒤집으시려면 서명 알고리즘·공개키 배포 방식·`iss`/`aud`·사용자 식별자 클레임 이름을 주세요. 그 경우 위 노출 조건은 사라집니다.

## 4.1 백엔드 `/internal/v1` 소비 — **§9 에 없는 것이 있습니다**

`app/core/adapters.py` 의 `BackendLedgerSource` 가 §9.1 · §9.2 를 읽습니다(읽기 전용, 커서 페이징 끝까지). 다만 엔진이 필요한 것 중 셋이 §9 에 없습니다.

| 필요한 것 | §9 | 지금 처리 |
|---|---|---|
| **일별 종가 시계열** | `currentPrice` 한 점뿐 | `asOf` 하루치만 채웁니다 |
| **섹터** | 없음 | "미분류" |
| **입출금 이력** | 없음 (`/api/v1/deposits` 는 사용자 API) | 빈 값 |
| 수수료 | 거래 항목에 없음 | 0 |

**시계열이 가장 큽니다.** 위험 지표는 60거래일이 필요한데(`min_history_days`) 한 점으로는 계산이 안 되어 `INSUFFICIENT_DATA` 가 나갑니다. 명세대로의 정상 동작이지만, 그 상태로는 포트폴리오 진단·기여도 분석이 사실상 비활성입니다. 없는 값을 채워 넣으면 조용히 틀린 숫자가 나가므로 지어내지 않았습니다.

셋 중 무엇을 백엔드가 주고 무엇을 AI 가 자체 조달할지 정해 주세요. 수수료가 0 이면 수익률이 실제보다 좋게 나옵니다. 시계열은 AI 가 KRX 에서 직접 받는 선택지도 있습니다(`ai/docs/api-spec.md` §11).

## 5. 요약 — 결정이 필요한 항목

| # | 항목 | 결정 주체 |

4·5번은 AI 파트에서 확정해 구현까지 마쳤습니다(FINCH-30). **§4 의 배포 조건(AI 서버 외부 비노출)** 만 인프라 쪽에서 확인해 주시면 됩니다.

1·3번은 여전히 백엔드 결정 대기입니다. 다만 둘 다 봉투/코드 매핑 문제라 AI 구현을 막지는 않습니다 — 우리는 `docs/openapi.json` 대로 응답합니다.
